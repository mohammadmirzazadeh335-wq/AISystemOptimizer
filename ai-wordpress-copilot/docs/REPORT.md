## ۱. خلاصه اجرایی

افزونه `ai-wordpress-copilot/` به‌صورت ماژولار و شی‌گرا (namespace `AIWC\`، PHP 7.4+، استاندارد کدنویسی وردپرس)
روی **یک نصب واقعی وردپرس** (هسته WordPress/WordPress، PHP 8.3، دیتابیس SQLite، سرور HTTP واقعی) ساخته و
در ۱۲ فاز تکمیل شد. معماری از همان هسته اولیه تکامل یافت (بازنویسی از صفر انجام نشد) و همه قابلیت‌های
فازهای قبلی حفظ شدند. معیار موفقیت محقق شد: یک دستور زبان طبیعی مانند «یک وب‌سایت فروشگاهی مدرن بساز»
صفحات واقعی، قابل مشاهده و قابل ویرایش می‌سازد — همراه با برنامه اجرایی، بررسی سئو و گزارش نتایج.

## ۳. قابلیت‌های تکمیل‌شده (همه تست‌شده)

### اتصال هوش مصنوعی
- ارائه‌دهنده سازگار با OpenAI با Base URL / کلید / مدل / هدرهای سفارشی / پارامترهای سفارشی / دما / top_p / حداکثر توکن / timeout / retry / streaming / محدودیت توکن و نرخ — بدون مدل hardcodeشده.
- **تشخیص قابلیت مدل**: tool calling، streaming، streaming tool calls، JSON mode، پنجره متن — با fallback امن برای مدل‌های بدون tool calling (پروتکل JSON متنی).
- مدیریت خطاهای دقیق و امن (بدون نمایش خطای خام یا راز): کلید نامعتبر، Base URL خراب، مدل ناموجود، rate limit، طول متن، timeout، خطای اتصال، پاسخ نامعتبر، tool calling پشتیبانی‌نشده، آرگومان نامعتبر.

### گفت‌وگوی جریانی (Streaming)
- رویدادهای SSE: `start/delta/plan/tool_call/tool_args/step/review/usage/status/done/error` — متن تدریجی، وضعیت، توکن‌ها، فراخوانی ابزار، مراحل عامل، نتیجه ابزار، تشخیص پایان.
- مونتاژ قطعات ناقق JSON در tool call های جریانی؛ fallback خودکار به حالت غیرجریانی برای مدل‌های بدون streaming؛ توقف (stop) و ادامه پس از قطع اتصال.

### سازنده وب‌سایت
- **موتور طراحی**: هدر/فوتر/هیرو/ناوبری/مگامنو/سایدبار/شبکه+کارت محصول/شبکه دسته/قیمت‌گذاری/نظرات/سؤالات/تماس/خبرنامه/گالری/بلاگ/CTA/ویژگی‌ها/آمار/لندینگ + صفحات اختصاصی + کامپوننت‌های قابل استفاده مجدد (۲۱ نوع بخش).
- **سامانه طراحی متمرکز**: رنگ‌ها/فونت‌ها/اندازه تیترها/گردی/سایه/فاصله/عرض کانتینر/دکمه‌ها/نقاط شکست — اعمال با زبان طبیعی («رنگ اصلی را سرمه‌ای کن») + خروجی CSS متغیرها.
- **گوتنبرگ**: ساخت/ویرایش/حذف/جابجایی بلوک‌ها، گروه‌ها، ستون‌ها، صفحات کامل، Global Styles — خروجی بلوک معتبر واقعی (با اعتبارسنجی balance).
- **المنتور**: صفحات/کانتینر/ویجت‌ها/چیدمان/تایپوگرافی/رنگ‌ها/تصاویر/فاصله‌ها — ساختار `_elementor_data` سازگار با نسخه نصب‌شده (containers در نسخه‌های جدید).
- تشخیص صفحه‌ساز با اولویت **Elementor > Gutenberg > پوسته فعال** + بازنویسی توسط ادمین (`preferred_builder`).

### بازطراحی صفحه
- جریان کامل: خواندن صفحه ← تحلیل (فهرست تیترها/متن‌ها/تصاویر/لینک‌ها/تعداد کلمات) ← استخراج محتوای مهم ← بازبینی طراحی ← پیشنهاد (با حفظ ۱۰۰٪ محتوا — chunk کردن بخش‌ها) ← ساخت پیش‌نمایش (پیش‌نویس با meta) ← بررسی مشکلات ← اعمال پس از تأیید (`confirm`) ← مقایسه قبل/بعد.
- حذف هرگز محتوای اصلی بدون اجازه انجام نمی‌شود؛ اعمال با snapshot محافظت می‌شود.
- **محدودیت اعلام‌شده**: ابزار اسکرین‌شات مرورگر در این محیط در دسترس نبود؛ مقایسه بصری قبل/بعد گزارش نمی‌شود و این موضوع در خروجی `compare` به‌صورت `screenshots.available=false` اعلام می‌شود.

### سئو
- تحلیل صفحه/سایت با نمره و مسائل کدگذاری‌شده + پیشنهاد اصلاح؛ گزارش سایت با قابلیت ازسرگیری (resume).
- **بررسی لینک‌های خارجی**: استخراج، حذف تکرار، وضعیت HTTP، تشخیص 404/ریدایرکت/timeout/SSL/غیرقابل‌دسترس، صفحه مبدأ، متن لنگر، گزارش گروهی + پیشنهاد اصلاح — با صف، همزمانی محدود، کش، ازسرگیری و لغو.
- **محافظ SSRF**: مسدودسازی آدرس‌های داخلی/localhost/IP خصوصی/متادیتای ابری/پروتکل‌های غیرمجاز + اعتبارسنجی هر hop ریدایرکت + استفاده از WP HTTP API.

### ووکامرس
- محصول متغیر (ویژگی‌ها + تنوع‌ها با CRUD استاندارد WC)، دسته‌ها (ایجاد/به‌روزرسانی/فهرست)، موجودی (موجودی/حد هشدار/Backorders/وضعیت)، تصاویر (کتابخانه رسانه + دانلود URL با محافظ SSRF)، تحلیل محصول (نمره/موارد جذب‌شده/اصلاحات)، توضیحات + سئو (Yoast/AIOSEO + بررسی طول‌ها)، طراحی صفحه فروشگاه/دسته با Design_Engine.
- **تأیید اجباری ادمین**: تغییر قیمت/قیمت حراجی/موجودی/وضعیت موجودی بدون `confirm` اجرا نمی‌شود؛ یک رکورد تأیید (audit trail) ساخته می‌شود و عملیات `needs_confirmation` در صف تأیید می‌رود (اثبات سرتاسری در woo_test).

### برنامه‌ریزی، بازبینی و ضدتوهم
- ابزار مجازی `create_plan` قبل از فرمان‌های پیچیده؛ نمایش برنامه در UI و رویداد `plan`.
- بازبینی خودکار (`self_review`) روی نتیجه هر ابزار؛ رویداد `review` در استریم.
- ادعاهای پاسخ فقط از نتایج واقعی ابزارها (سیاست system prompt + بررسی در تست‌ها).

### ایمنی
- صف تأیید ادمین + snapshot/بازگردانی برای تغییرات مهم + **قفل اجرای همزمان (run-lock)** + محافظ replay شناسه tool_call.
- بدون هیچ ابزار اجرای PHP/Shell/SQL؛ اعتبارسنجی آرگومان ابزارها؛ محافظت prompt injection؛ پنهان‌سازی کامل کلید API. جزئیات: [SECURITY.md](SECURITY.md) — `security_test` **29/29**.

### رابط مدیریت
- چت با استریم/ابزارها/برنامه/مراحل/پیشرفت/پیش‌نمایش/خطا/مصرف توکن/توقف/بازگردانی/ادامه.
- بخش جدید **Website Builder** (صفحات طراحی‌شده، سامانه طراحی، کامپوننت‌های قابل استفاده مجدد) و **Reports** (عملیات، مصرف توکن، موفق/ناموفق، مسائل سئو، وظایف، تغییرات اخیر).
- تنظیمات AI کامل: کلید/Base URL/مدل/دما/top_p/حداکثر توکن/timeout/retry/streaming/دستور سیستمی/مجوز ابزارها/سطح خودمختاری — همه دکمه‌ها به REST متصل و فعال.

## ۵. نصب روی سایت واقعی

1. دریافت `dist/ai-wordpress-copilot.zip` (قابل نصب مستقیم از wp-admin).
2. **افزونه‌ها ← افزودن ← بارگذاری افزونه** ← نصب ← فعال‌سازی.
3. پیکربندی ارائه‌دهنده در **AI Copilot ← API Connection** + تست اتصال.
4. شروع با دستور زبان طبیعی در **AI Chat**.

## ۶. محدودیت‌های صادقانه اعلام‌شده

- **اسکرین‌شات/اتوماسیون مرورگر** در محیط ساخت (php-wasm sandbox) در دسترس نبود؛ UI در لایه REST + سیم‌کشی ایستای JS آزمون شد (در `ui_test.py` مستند شده). مقایسه بصری قبل/بعد در بازطراحی، `screenshots.available=false` گزارش می‌کند.
- **تست با ارائه‌دهنده واقعی** نیازمند کلید API واقعی است؛ مجموعه `coverage_test.py` آن ناحیه را با `AIWC_REAL_API_KEY` اجرا می‌کند و در نبود کلید، وضعیت SKIP ثبت می‌شود (شکست محسوب نمی‌شود). همه تست‌های دیگر با mock سازگار با OpenAI روی همان مسیرهای واقعی REST/SSE اجرا شده‌اند.
- نسخه‌بندی PHP 7.4+ اعلام شده؛ محیط آزمون PHP 8.3 است.
