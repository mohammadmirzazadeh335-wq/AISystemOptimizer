# ساخت نسخهٔ اجرایی و نصب‌کنندهٔ ویندوز — زرین هرمز

این سند دستورهای واقعیِ ساخت نسخهٔ اجرایی و نصب‌کننده را می‌دهد و **صادقانه** می‌گوید
چه چیزی در این محیط ساخته شده و چه چیزی ساخته نشده است.

## وضعیت واقعی (این نسخه)

| قلم | فایل | ساخته شد؟ |
|-----|------|-----------|
| اسکریپت ساخت نسخهٔ اجرایی | [`packaging/zarrin_hormoz.spec`](../packaging/zarrin_hormoz.spec) | ✅ نوشته و بازبینی شد |
| اسکریپت نصب‌کننده (Inno Setup) | [`packaging/zarrin_hormoz.iss`](../packaging/zarrin_hormoz.iss) | ✅ نوشته و بازبینی شد |
| اسکریپت ساخت روی ویندوز | [`packaging/build_windows.ps1`](../packaging/build_windows.ps1) | ✅ نوشته شد |
| اسکریپت اعمال به‌روزرسانی | [`packaging/apply_update.ps1`](../packaging/apply_update.ps1) | ✅ نوشته شد |
| ابزار ساخت مانیفست | [`packaging/make_release_manifest.py`](../packaging/make_release_manifest.py) | ✅ نوشته و **آزمون شده** |
| نصب‌کنندهٔ `.exe` | `packaging/output/ZarrinHormoz-0.7.0-setup.exe` | ❌ ساخته نشد |

**چرا نصب‌کننده ساخته نشد:** این محفظه (sandbox) لینوکس است و نه ویندوز، نه
PyInstaller و نه کامپایلر Inno Setup (`iscc.exe`) روی آن وجود دارد و نصب آن‌ها هم
ممکن نیست. هیچ فایل `.exe` جعلی ساخته نشده است. برای تولید نصب‌کننده باید
دستورهای زیر روی یک ماشین ویندوز ۱۰/۱۱ (۶۴ بیتی) اجرا شود.

## ساخت روی ویندوز

```powershell
# ۱) پیش‌نیازها
py -3.11 -m venv .venv-build
.\.venv-build\Scripts\pip install -r requirements.txt pyinstaller==6.11.1
winget install -e --id JRSoftware.InnoSetup   # نسخهٔ ۶

# ۲) ساخت پوشهٔ اجرایی + نصب‌کننده + مانیفست
pwsh -File packaging\build_windows.ps1 -Version 0.7.0 -SigningKey C:\keys\release_signing_key.pem
```

خروجی‌ها:

```
dist\ZarrinHormoz\ZarrinHormoz.exe              # برنامه (بدون کنسول)
dist\ZarrinHormoz\ZarrinHormoz-console.exe      # برای پشتیبانی/به‌روزرسانی
packaging\output\ZarrinHormoz-0.7.0-setup.exe   # نصب‌کننده
dist\releases-0.7.0.json                        # مانیفست به‌روزرسانی (امضاشده)
```

## چه چیزی نصب‌کننده انجام می‌دهد

- **پیش‌نیازها:** ویندوز ۶۴ بیتی و نسخهٔ ۱۰ یا بالاتر بررسی می‌شود؛ فضای آزاد
  پوشهٔ داده (حداقل ۵۱۲ مگابایت) و قابل‌نوشتن بودن آن آزموده می‌شود. اگر
  پیش‌نیازی برآورده نشود، نصب با پیام فارسی متوقف می‌شود و فایل نیمه‌نصب باقی
  نمی‌ماند (Inno Setup پس از خطا فایل‌های نوشته‌شده را برمی‌گرداند).
- **مسیرها:** فایل‌های برنامه در `{autopf}\ZarrinHormoz` و داده‌ها در
  `%LOCALAPPDATA%\ZarrinHormoz` (`data/`, `backups/`, `logs/`, `config.json`).
- **میان‌برها:** منوی شروع (برنامه، خط فرمان، راهنمای نصب، حذف) و در صورت انتخاب،
  میزکار و نوار وظیفه.
- **پیش از اولین اجرا:** `ZarrinHormoz-console.exe backup --note "..."` یک پشتیبان
  **تأییدشده** می‌گیرد؛ اگر پشتیبان‌گیری شکست بخورد، نصب ادامه می‌یابد اما هشدار
  در گزارش نصب ثبت می‌شود و برنامه در اجرای بعدی آن را در هشدارها نشان می‌دهد.
- **حذف:** حذف‌کننده پوشهٔ داده را **پاک نمی‌کند** مگر کاربر در صفحهٔ «داده‌های
  حسابداری» صریحاً گزینهٔ دوم را انتخاب کرده و در پایان همان مسیر را دوباره تأیید
  کند. پیش‌فرض همیشه «داده‌ها حفظ شوند» است.

## ارتقا از نسخهٔ قبل

1. `ZarrinHormoz-console.exe update stage --package <setup.exe>` — بسته بررسی
   (SHA-256 + امضای Ed25519)، پشتیبان خودکار گرفته و نشانگر `updates\pending.json`
   نوشته می‌شود.
2. برنامه بسته می‌شود و `packaging\apply_update.ps1` نصب‌کننده را در حالت
   `/SILENT` اجرا می‌کند (پوشهٔ داده دست‌نخورده می‌ماند).
3. `ZarrinHormoz-console.exe doctor` سلامت را بررسی می‌کند (پایگاه داده، ساختار،
   مهاجرت‌ها، پوشهٔ پشتیبان). اگر بررسی ناموفق باشد، اسکریپت
   `update rollback --confirm "بازیابی"` را اجرا می‌کند و نسخهٔ قبلی داده برمی‌گردد.

## محدودیت شناخته‌شده

- نسخهٔ اجرایی و نصب‌کننده در این محیط ساخته نشده‌اند (بالا توضیح داده شد).
- کد امضای بسته با کلید خصوصی مخزن نصب انجام نشده است؛ ساختار امضا و بررسی آن
  پیاده و آزمون شده، اما کلید انتشار واقعی وجود ندارد. تا وقتی کلید عمومی در
  تنظیمات ثبت نشود، برنامه هیچ بسته‌ای را «تأییدشده» نمی‌داند.
- آیکون `packaging/zarrin_hormoz.ico` همراه نیست؛ اسکریپت ساخت در نبود آن هم
  کار می‌کند (بدون آیکون سفارشی). افزودن آیکون تنها یک فایل است و به کد مربوط نیست.
