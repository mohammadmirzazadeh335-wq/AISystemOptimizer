# ۷) اتصال به حسابداری: الگوهای ثبت سند

## اصل کار

خزانه هیچ سندی را «دستی» ثبت نمی‌کند؛ هر عملیات با یک **الگوی ثبت**
(Posting Pattern) به سند دوطرفه تبدیل می‌شود. الگوها در تنظیمات (`posting_rules`)
نگه‌داری می‌شوند و از صفحهٔ `treasury_settings` قابل ویرایش‌اند. هیچ کد حسابی در
منطق خزانه hard-code نشده است.

## عملیات‌های قابل الگوسازی (`POSTING_OPERATIONS`)

| کلید | عنوان | رویداد |
|------|-------|--------|
| `treasury.receipt_cash` | دریافت نقدی | ثبت دریافت با صندوق |
| `treasury.receipt_bank` | دریافت بانکی | ثبت دریافت با حساب بانکی |
| `treasury.receipt_cheque` | دریافت چک | ثبت دریافت چکی |
| `treasury.payment_cash` | پرداخت نقدی | ثبت پرداخت با صندوق |
| `treasury.payment_bank` | پرداخت بانکی | ثبت پرداخت با حساب |
| `treasury.payment_cheque` | صدور چک | ثبت پرداخت چکی |
| `treasury.cheque_collected` | وصول چک | تغییر وضعیت به `collected` |
| `treasury.cheque_bounced` | برگشت چک | تغییر وضعیت به `bounced` |
| `treasury.cheque_cleared` | پاس شدن چک صادره | تغییر وضعیت به `paid` |
| `treasury.transfer` | انتقال | حرکت بین دو منبع نقدی |
| `treasury.bank_fee` | کارمزد بانکی | هزینهٔ بانکی انتقال |

## منابع مبلغ (`AMOUNT_SOURCES`)

`amount` (مبلغ سند)، `fee` (کارمزد)، `fund` (مبلغ از حساب صندوق/بانک)،
`fund_from` / `fund_to` (مبلغ مبدأ/مقصد). منابع پویا (`DYNAMIC_SOURCES`) در زمان
ثبت با شناسهٔ حساب واقعی جایگزین می‌شوند.

> نکته: `posting_service.build_entry` سطرهای با مبلغ صفر را حذف می‌کند؛ بنابراین
> هر کلید منبعی که در الگو استفاده شده باید در `components` وجود داشته باشد،
> وگرنه ساخت سند شکست می‌خورد.

## کدهای حساب پیش‌فرض

| کد | عنوان |
|----|-------|
| `101002` | حساب‌های دریافتنی (مشتریان) |
| `101003` | موجودی کالا |
| `101005` | صندوق‌ها |
| `101006` | حساب‌های بانکی |
| `101007` | چک‌های در جریان وصول |
| `201001` | حساب‌های پرداختنی (تأمین‌کنندگان) |
| `201004` | چک‌های پرداختنی |
| `502001` | هزینهٔ حقوق و دستمزد |
| `502004` | هزینهٔ بانکی |
| `503001` | هزینه‌های متفرقه |

این کدها فقط **مقادیر پیش‌فرض اولیه** هستند؛ هر نصب می‌تواند آن‌ها را در
تنظیمات الگوهای ثبت تغییر دهد.

## یکتایی و جلوگیری از تکرار

- `trs_receipts.idempotency_key`، `trs_payments.idempotency_key`،
  `trs_transfers.idempotency_key` یکتا هستند.
- کلیدهای رایج: `receipt:{id}:journal`، `payment:{id}:journal`،
  `transfer:{id}:journal`، `*-void`، `cheque:{id}:{action}`، `statement-line:{id}:adjust`.
- تلاش برای ثبت دوباره `ConflictError` می‌دهد و سند دوم ساخته نمی‌شود.

## ابطال و اصلاح

`reverse_journal` سند برگشت (بدون حذف سند اصلی) می‌سازد. هیچ سند ثبت‌شده‌ای
حذف یا ویرایش نمی‌شود؛ اصلاح فقط از مسیر ابطال/برگشت یا سند اصلاحی انجام می‌گیرد.

## هم‌ترازی با فازهای قبل

- اسناد خرید/فروش (فاز ۳) با تخصیص‌های خزانه (`trs_allocations`) تسویه می‌شوند.
- ماندهٔ حساب‌های `101005`/`101006` همیشه با ماندهٔ صندوق‌ها/بانک‌ها برابر است،
  چون هر دو از یک سند مشترک مشتق می‌شوند.
