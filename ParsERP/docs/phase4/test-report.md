## آزمون دستی/E2E

سناریوی سرتاسری ``trs_smoke`` پیش‌تر و پیش از بازسازی محیط اجرا و سبز بود:
سند فروش → دریافت `RCV-1405-0001` (سند ۲، صندوق `10,006,000.00`) → پرداخت
`PAY-1405-0001` (سند ۳) → چک `RCV-1405-0002` از `received` به `collected` (سند ۴) →
انتقال `TRF-1405-0001` (سند ۵) → تطبیق خودکار `{'matched': 1, 'ambiguous': 0, 'unmatched': 0}`
→ داشبورد `cash_total 12,010,000.00`, `bank_total 96,495,000.00`.
این فایل در بازسازی محیط سندباکس از دست رفت؛ همان مسیر اکنون توسط
`test_treasury_vouchers.py` و `test_treasury_reports.py` پوشش داده می‌شود.

## مشکلاتی که در جریان آزمون پیدا و رفع شد

| مشکل | علت | رفع |
|------|-----|-----|
| `TypeError: 'decimal.Decimal' object is not callable` در `transfers_page.py` | `MoneyEdit.amount` property است | حذف `()` در همهٔ صفحه‌های خزانه |
| `AttributeError: CurrencyService has no list_currencies` | نام متد اشتباه | استفاده از `currency_choices()` |
| ماندهٔ منفی/سند دوم در تست‌های تکراری | نبود بررسی idempotency در مسیر دیالوگ | کلید یکتا و `ConflictError` |
| `banks.movements == []` در آزمون UI | `selectRow` در چیدمان RTL در Qt 6.12 ردیف را انتخاب نمی‌کند | آزمون با `setCurrentIndex` + `selectionModel().select(...)` |
| آزمون نقش‌ها `ImportError` | `DEFAULT_ROLE_PERMISSIONS` وجود ندارد | استفاده از `DEFAULT_ROLE_TEMPLATES` |
| تست داشبورد عدد کامل را انتظار داشت | قالب نمایش «۹۹,۹۹۹,۰۰۰.۰۰ IRR» | اصلاح انتظار آزمون به مقدار قالب‌بندی‌شده |
