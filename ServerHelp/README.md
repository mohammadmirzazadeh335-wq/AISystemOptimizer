# Server Help — راهنمای فارسی

**Server Help** یک برنامه کوچک ویندوزی است که کارش این است: شما نسخه ماینکرفت را انتخاب می‌کنید،
دکمه را می‌زنید، و برنامه در کمتر از یک دقیقه:

1. اینترنت شما را **تشخیص** می‌دهد (DNS، بازبودن پورت، فیلتر شدن اتصال مستقیم)
2. اگر لازم باشد روی **Cloudflare WARP** یک تونل می‌سازد و **کم‌پینگ‌ترین endpoint** را خودش پیدا می‌کند
3. فقط ترافیک **همان سرور بازی** را از تونل عبور می‌دهد؛ بقیه اینترنت شما دست‌نخورده می‌ماند
4. سیستم را برای بازی **بهینه** می‌کند (طرح انرژی، اولویت پردازش، آزادسازی حافظه، فایروال، فلگ‌های JVM)
5. **خود بازی را اجرا می‌کند** و اگر بخواهید، مستقیم وارد سرور می‌شود

> سرور پیش‌فرض: `smp3.mcsh.io` پورت `11005` — از تب «سرورها» می‌توانید هر سرور دیگری اضافه کنید.

---

## دانلود و اجرا

1. به صفحه **Releases** همین مخزن بروید و `ServerHelp.exe` را دانلود کنید.
2. هرجایی خواستید بگذارید (Desktop، فلش، …) — نیازی به نصب ندارد.
3. **راست‌کلیک → Run as administrator** (برای ساخت کارت شبکه TUN، مسیرها، فایل hosts و طرح انرژی،
   دسترسی ادمین لازم است؛ بدون آن برنامه کار می‌کند ولی تونل ساخته نمی‌شود).
4. اول ویندوز ممکن است هشدار SmartScreen بدهد: **More info → Run anyway**
   (فایل امضای تجاری ندارد). SHA-256 هر نسخه کنار همان فایل منتشر می‌شود:

   ```powershell
   certutil -hashfile ServerHelp.exe SHA256
   ```

   **کدام بیلد را دارم؟** نسخه‌ای که CI می‌سازد، شماره بیلد را در خودش دارد: در تب **تنظیمات** پایین صفحه
   می‌نویسد `Server Help v1.0.0.57` و همان عدد در تگ ریلیز (`serverhelp-v1.0.0-57`) و اولین خط لاگ هم هست.

   هر نسخه‌ای که ساخته می‌شود، اول یک **self test** را رد می‌کند: برنامه همه کانفیگ‌هایی
   که می‌تواند بسازد (پروکسی ساده، زنجیره دو مرحله‌ای، مسیر OpenVPN با رزولوورهای سرور،
   حالت فقط-DNS) را می‌نویسد و خودِ موتور sing-box آن‌ها را بررسی می‌کند؛ اگر یکی رد شود،
   بیلد شکست می‌خورد و دلیلش منتشر می‌شود.

   خودِ موتور تونل هم در CI پین شده است: آرشیو `sing-box` با sha256 منتشرشده همان
   release در گیت‌هاب و آرشیو `wintun` با sha256 اعلام‌شده در wintun.net بررسی می‌شود و
   اگر تطابق نداشته باشد، بیلد شکست می‌خورد.

## بهینه‌سازی نسخه انتخاب‌شده

به‌محض انتخاب یک نسخه، پنل کنار آن نشان می‌دهد دقیقاً چه کاری روی همان نسخه انجام می‌شود
(لودر شناسایی‌شده، حافظه، جمع‌کننده زباله، پرچم‌ها، فایل‌های جاافتاده). همان لحظه ساختن فرمان اجرا
در پس‌زمینه انجام می‌شود، پس کتابخانه‌ها/assetهای جاافتاده **قبل از** زدن دکمه دانلود می‌شوند و
پایپ‌لاین در همان یک دقیقه می‌ماند. آنچه تصمیم گرفته می‌شود:

| موضوع | قاعده |
|---|---|
| حافظه | از RAM واقعی سیستم؛ سقف ۶۰٪ رم و حداکثر ۸ گیگ (بیشتر از این برای ماینکرفت کندتر است)؛ نسخه‌های موددار +۱ گیگ |
| جمع‌کننده | Aikar/G1GC برای نسخه‌های جدید؛ CMS برای ۱.۱۲.۲ و قدیمی‌تر روی Java 8 |
| لودر | Forge/NeoForge: خاموش‌کردن پنجره splash و بالا بردن مهلت شبکه؛ LabyMod: هشدار تنظیمات داخلی |
| شبکه | `-Djava.net.preferIPv4Stack=true` وقتی سرور IPv4 است (علت رایج خطای join) |
| کدگذاری | روی Java 18+ خروجی UTF-8 می‌شود تا چت فارسی سالم بماند |
| تکراری‌ها | هر پرچمی که کانفیگ خود نسخه قبلاً ست کرده باشد نادیده گرفته می‌شود |
| اختیاری | تیک «Java OpenGL pipeline» در تنظیمات، برای درایورهای اینتل که با D3D مشکل دارند |

## شمارش معکوس یک‌دقیقه‌ای

هنگام زدن دکمه، برنامه مراحل را در تب «خانه و اجرا» نشان می‌دهد و زمان می‌شمارد:

| مرحله | کاری که انجام می‌شود |
|---|---|
| بررسی پیش‌نیازها | پیدا کردن پوشه بازی، نسخه، Java |
| تشخیص شبکه | رزولو دامنه، تست TCP، پینگ واقعی Minecraft (SLP) |
| تصمیم مسیر | اتصال مستقیم سالم است؟ → تونل لازم نیست. فیلتر است؟ → تونل WARP |
| بهینه‌سازی سیستم | طرح انرژی، throttle شبکه، فایروال، حافظه، تایمر ۱ms |
| اسکن WARP | رتبه‌بندی آدرس‌های anycast کلادفلر بر اساس تأخیر واقعی |
| حساب WARP | ساخت/استفاده از کلید و ثبت خودکار (فقط یک‌بار) |
| ساخت و اجرای تونل | `sing-box` با کانفیگ split-tunnel (فقط IP سرور از تونل می‌رود) |
| تأیید تونل | پینگ واقعی بازی از داخل تونل + انتخاب endpoint |
| تثبیت آدرس | ثبت IP در فایل `hosts` تا بازی به همان آدرس برود |
| اجرا | `javaw.exe` با فلگ‌های بهینه + ورود خودکار به سرور |

اگر تونل در دسترس نباشد، برنامه خودش به حالت «فقط اصلاح DNS» می‌رود و باز هم بازی را اجرا می‌کند؛
دلیلش را در گزارش (تب «گزارش») می‌نویسد.

## چه چیزهایی داخلش هست

* **تشخیص قبل از کار**: برنامه اول تست می‌کند. اگر اینترنت شما مشکلی ندارد، تونل بی‌دلیل بالا نمی‌آید.
* **تونل split**: فقط IP سرور از تونل می‌رود (`route_address` روی اینترفیس TUN). دیسکورد، مرورگر و
  بقیه چیزها از مسیر عادی اینترنت شما می‌روند — پس پینگ بقیه کارهایتان خراب نمی‌شود.
* **انتخاب کم‌پینگ‌ترین مسیر**: چند endpoint در گروه `urltest` گذاشته می‌شود و sing-box خودش
  سریع‌ترین را انتخاب می‌کند؛ برنامه هم پینگ هر endpoint را از Clash API می‌خواند.
* **بهینه‌سازی سیستم**: کم‌کردن Network Throttling، اولویت بالای java، آزادسازی حافظه برنامه‌های
  بی‌کار، قانون فایروال برای بازی و تونل، تایمر ۱ میلی‌ثانیه‌ای. **طرح انرژی دست‌نخورده می‌ماند**
  مگر خودتان در تب «بهینه‌سازی» تیکش را بزنید (پسورد ویندوز،آنتی‌ویروس و Windows Update هم دست‌کاری نمی‌شوند).
* **فلگ‌های JVM**: ترکیب Aikar + حافظه خودکار بر اساس RAM سیستم + `-Dfile.encoding=UTF-8`
  (برای چت فارسی در بازی).
* **بازگردانی**: وقتی بازی بسته شد یا دکمه «توقف و بازگردانی» را زدید، hosts، مسیرها، طرح انرژی و
  تغییرات رجیستری به حالت قبل برمی‌گردند.

## تب «اتصالات» — پروکسی، DNS و کانفیگ دستی

برنامه علاوه بر تشخیص خودکار (WARP + انتخاب کم‌پینگ‌ترین endpoint)، اجازه می‌دهد **خودتان**
اتصال‌ها را وارد کنید. هر اتصالی که اضافه می‌کنید، مثل بقیه مسیرها در لحظه اجرا تست می‌شود و اگر
از بقیه سریع‌تر باشد، ترافیک بازی از آن عبور می‌کند.

### چه چیزهایی قابل وارد کردن است؟

| نوع | نمونه ورودی |
|---|---|
| **SOCKS5** | `1.2.3.4:1080` یا `1.2.3.4:1080:user:pass` یا `socks5://user:pass@1.2.3.4:1080` |
| **HTTP/HTTPS** | `http://1.2.3.4:8080` یا `1.2.3.4:8080:user:pass` |
| **MTProto (تلگرام)** | `tg://proxy?server=1.2.3.4&port=443&secret=dd...` یا `1.2.3.4:443:dd...` |
| **DNS** | `1.1.1.1`، `:53`، `udp://1.1.1.1`، `tcp://8.8.8.8`، `tls://1.1.1.1:853`، `https://cloudflare-dns.com/dns-query` |
| **WireGuard** | کل متن `[Interface]/[Peer]` فایل کانفیگ (PrivateKey، Address، PublicKey، Endpoint، MTU) |
| **کانفیگ کامل sing-box** | JSON کاملی که `inbounds`/`outbounds` دارد (پروکسی + پورت SOCKS محلی) |
| **outbound آماده sing-box** | یک JSON با فیلد `type` (مثلاً `vless`، `vmess`، `trojan`، `shadowsocks`، `hysteria2`، `tuic`) |
| **لینک اشتراک** | `vless://…`، `vmess://…`، `trojan://…`، `ss://…`، `hysteria2://…`، `tuic://…` (شامل `ws`/`grpc`/`reality`/`tls`) |

> **درباره MTProto:** پروکسی MTProto فقط می‌تواند ترافیک **تلگرام** را حمل کند (سرور آن را به
> دیتاسنترهای تلگرام می‌فرستد و مقصد را خودش انتخاب می‌کند)، پس بازی ماینکرفت از آن عبور نمی‌کند.
> برنامه این را پنهان نمی‌کند: در ستون **Carries** نوشته می‌شود «Telegram only»، عدد تأخیر با برچسب
> `(tg)` علامت می‌خورد و ورودی از لیست «Pinned game route» حذف می‌شود. در عوض همین ورودی‌ها واقعاً
> کار می‌کنند و تست می‌شوند:
>
> | دکمه | کاری که می‌کند |
> |---|---|
> | **Verify MTProto for real** | handshake واقعی (obfuscated2 / `dd` secured / `ee` fake-TLS) و بعد یک رفت‌وبرگشت واقعی `req_pq_multi` → `resPQ`؛ فقط پروکسی‌ای که واقعاً به تلگرام وصل است پاس می‌شود |
> | **Rank Telegram data centres** | تأخیر واقعی هر ۵ دیتاسنتر را از داخل همان پروکسی می‌گیرد و سریع‌ترین را پیشنهاد می‌دهد (DC را روی همان ورودی ذخیره می‌کند) |
> | **Copy tg:// link** | لینک `tg://proxy?...` همان ورودی را در کلیپ‌بورد می‌گذارد تا در تلگرام وارد کنید |
>
> در لاگ نشان داده می‌شود که سکرت به کدام حالت parse شده (`fake-TLS`، `secured (dd)`، `classic`) و
> کدام دامنه به‌عنوان SNI استفاده می‌شود؛ اگر سکرت ناقص باشد، دلیلش نوشته می‌شود.

### تست تک‌تک و گرفتن تأخیر

* **Test selected** — فقط اتصال انتخاب‌شده را تست می‌کند.
* **Test all and take delays** — همه اتصال‌های روشن را یکی‌یکی (در صف) تست می‌کند؛ نتیجه در ستون‌های
  «Delay» و «Status» ذخیره می‌شود و در لاگ هم می‌آید.
* پروکسی‌ها با یک **هند‌شیک واقعی** و سپس یک **پینگ واقعی Minecraft** از داخل همان پروکسی سنجیده
  می‌شوند؛ DNS با رزولو واقعی یک دامنه؛ WireGuard/کانفیگ‌های sing-box با بالا آوردن یک تونل
  آزمایشی (بدون دست‌زدن به مسیرهای ویندوز) و بعد پینگ بازی؛ MTProto با یک probe واقعی.
* «Test timeout (ms)» سقف انتظار هر تست است (پیش‌فرض ۳۰۰۰).

### تشخیص خط: امروز مشکل از کجاست؟ (Diagnose the line)

دکمه **Diagnose the line** در تب اتصالات، همین حالا و بدون دست‌زدن به تنظیم‌های ویندوز، پنج
چیز را جداگانه امتحان می‌کند:

| آزمون | اگر رد شود یعنی |
|---|---|
| یک اتصال TCP به آدرس بین‌المللی (`1.1.1.1:443`) | اینترنت بین‌الملل باز نیست |
| هند‌شیک TLS با یک دامنه خارجی | TLS فیلتر یا بازنویسی می‌شود |
| رزولو نام با DNS خود سیستم | DNS محلی جواب درست نمی‌دهد |
| پرسش DNS روی UDP به بیرون | DNS از سمت شبکه بسته است |
| خودِ سرور بازی (`smp3.mcsh.io:11005`) | مشکل فقط روی همان سرور است |

نتیجه یکی از این‌هاست: **Open**، **DNS broken**، **TLS blocked**، **National only**
(فقط اینترنت ملی)، **Fully filtered**، **Server blocked**. بعد از تشخیص، برنامه فقط
تنظیم‌های خودش را پیشنهاد و اعمال می‌کند: روشن‌کردن «DNS inside the tunnel» برای DNS خراب یا
اینترنت ملی، روشن‌کردن **Fragment TLS** وقتی TLS فیلتر است، و پیشنهاد «بهینه‌سازی مسیر بازی»
وقتی فقط خود سرور بسته است. هیچ چیز دیگری روی سیستم عوض نمی‌شود.

### پایداری، سرعت و تست خودکار

* **Stability selected** — پنج پینگ واقعی پشت‌سرهم (با فاصله کوتاه) به همان سرور بازی، از داخل
  همان مسیر؛ نتیجه در ستون **Quality (stability)** ذخیره می‌شود: کمینه/میانگین/بیشینه،
  **جیتر** و **درصد باخت**. عدد تک و آماره فرق دارند و همان جیتر و باخت است که در بازی حس می‌شود.
* **Stability all** — همین کار برای همه اتصال‌های روشن، یکی‌یکی و با فاصله.
* **Speed selected** — ۵۱۲ کیلوبایت دانلود واقعی از `speed.cloudflare.com` **از داخل همان
  مسیر** و ثبت سرعت، تا ببینید تونل چقدر پهنای باند می‌دهد.
* **Auto retest (minutes)** — اگر عددی جز صفر بگذارید، برنامه هر چند دقیقه یک‌بار تست تأخیر سبک
  را خودش انجام می‌دهد؛ وقتی بازی یا تونل در حال اجراست، یا تستی در جریان است، خودش صبر می‌کند.

### اشتراک (Subscription link)

اگر سرویس‌دهنده‌تان یک لینک اشتراک می‌دهد، دکمه **Subscription link** را بزنید: آدرس را بدهید
و بگویید از کجا بگیرد — مستقیم، یا از داخل یکی از اتصال‌های روشن (وقتی آن آدرس خودش بسته است).
فهرست «دریافت از طریق» فقط چیزهایی را نشان می‌دهد که واقعاً می‌توانند دانلود کنند: پروکسی
SOCKS5/HTTP، کانفیگ OpenVPN و WireGuard، کانفیگ دستی و کانفیگ کامل. اگر یکی از این‌ها انتخاب
کنید، برنامه برای همان یک دانلود یک نسخهٔ موقت از آن را بالا می‌آورد و بلافاصله خاموش می‌کند.
سرور DNS و پروکسی تلگرام در این فهرست نیستند، چون چیزی برای دانلود کردن ندارند.
پاسخ می‌تواند base64 باشد یا متن ساده؛ هر خط یک اتصال می‌شود و پیش‌نمایش قبل از افزودن
نشان داده می‌شود. اگر همان اشتراک را دوباره وارد کنید، نام‌ها تکراری نمی‌شوند (پس مسیر پین‌شده‌تان
گیج نمی‌شود).

### شکستن TLS (Fragment TLS)

بعضی وقت‌ها در اینترنت ملی خودِ هند‌شیک TLS شناسایی و قطع می‌شود. با روشن‌کردن **Fragment TLS**
برای هر ورودی (یا به‌عنوان پیش‌فرض همه)، برنامه `tls.fragment`، `record_fragment` و
`fragment_fallback_delay: 500ms` را به همان outbound اضافه می‌کند. روی ورودی‌هایی که TLS ندارند
هیچ چیزی اضافه نمی‌شود و کانفیگ دستی شما دست‌نخورده می‌ماند.

### دو زبان: فارسی و English

همه متن‌های برنامه دو‌زبانه نوشته شده‌اند (`L.T("فارسی", "English")`) و یک بازرسی خودکار در
بیلد، هر کمیت را کنترل می‌کند: اگر جایی یکی از دو زبان جا افتاده باشد، بیلد رد می‌شود. زبان را
از تب **تنظیمات → زبان برنامه** عوض می‌کنید؛ برنامه همان لحظه راست‌به‌چپ/چپ‌به‌راست می‌شود
(سرتیتر، کارت‌ها، نوار پیشرفت و اعداد فارسی) و انتخاب شما ذخیره می‌شود.

### OpenVPN (TunnelBear و سرویس‌های مشابه)

sing-box نسخه ۱.۱۴ خودش پروتکل OpenVPN را می‌فهمد، پس نیازی به نصب OpenVPN یا درایور
TAP نیست:

1. در تب **اتصالات** → **Add** → نوع را **OpenVPN profile** بگذارید.
2. **Load an .ovpn file…** را بزنید (فایل‌های TunnelBear یا هر سرویس‌دهنده دیگر) یا متن
   پروفایل را در کادر بچسبانید. برنامه `remote/proto`، گواهی‌ها، `tls-auth`/`tls-crypt`،
   cipher، mtu و مقدارهای ping را از داخل فایل می‌خواند و همان‌جا نشان می‌دهد چه چیزی
   پیدا شد و چه چیزی کم است.
3. اگر سرویس‌دهنده حساب می‌خواهد (TunnelBear می‌خواهد)، نام کاربری و رمز حساب را در
   همان پنجره بگذارید.
4. **Test** را بزنید: یک تونل آزمایشی بالا می‌آید (بدون دست‌زدن به مسیرهای ویندوز) و
   پینگ واقعی بازی از داخلش اندازه‌گیری می‌شود.

نکته مهم: ورودی OpenVPN مثل بقیه مسیرهاست — «بهینه‌سازی مسیر بازی» می‌تواند آن را
به‌عنوان گام اول یا گام دوم یک **زنجیره رله** هم امتحان کند، و در حالت پین‌شده فقط
آدرس سرور بازی از آن عبور می‌کند.

### DNS روی تونل (وقتی اینترنت ملی DNS را جواب نمی‌دهد)

تیک **DNS inside the tunnel** در تب اتصالات (پیش‌فرض روشن):

* در کانفیگ تونل یک بخش `dns` ساخته می‌شود که نام سرور بازی را از داخل همان مسیر
  حل می‌کند (`detour` روی مسیر انتخابی)، و اگر مسیر یک سرور OpenVPN باشد از
  **رزولوورهایی که خود سرور پوش می‌کند** استفاده می‌شود (`type: openvpn`).
* در زمان اجرا، خود برنامه هم نام سرور بازی را از داخل تونل می‌پرسد و جوابش را با
  جواب DNS سیستم مقایسه می‌کند. اگر فرق داشت یعنی DNS محلی دست‌کاری شده؛ آدرس درست
  در فایل `hosts` ثابت می‌شود تا بازی به آدرس اشتباه نرود و همین در گزارش می‌آید.
* دکمه **Test DNS inside the tunnel** دقیقاً همین مقایسه را نشان می‌دهد.
* رزولوشن خود پروکسی‌ها محلی است (نه از تونل)، وگرنه پروکسی برای پیدا کردن آدرس
  خودش به تونلی نیاز داشت که هنوز بالا نیامده.

### بهینه‌سازی مسیر بازی (کار Packet Raft، ولی فقط برای ماینکرفت)

دکمه **Optimise game route (real ping)** در تب اتصالات:

1. همه گزینه‌ها ساخته می‌شوند: خط مستقیم، هر اتصال روشن، و **زنجیره‌های دو مرحله‌ای**
   (گام دوم از داخل گام اول رد می‌شود؛ تعداد زنجیره‌ها را در همان تب تعیین می‌کنید).
2. هر کاندید در یک sing-box موقت (فقط پورت SOCKS محلی، بدون TUN، بدون تغییر مسیر)
   بالا می‌آید و با **هندشیک واقعی Minecraft** روی همان سرور واقعی اندازه‌گیری می‌شود.
3. نتیجه مرتب می‌شود و سریع‌ترین مسیر پیشنهاد و در صورت تأیید **پین** می‌شود؛ هر دو گام
   زنجیره ذخیره می‌شوند تا اجرای بعدی هم از همان مسیر برود.

این دقیقاً کاری است که پنل‌های معمولی نمی‌کنند: یک پروکسی می‌تواند ۲۰ میلی‌ثانیه دور
باشد و داخل بازی ۳۰۰ میلی‌ثانیه بدهد؛ فقط همان هندشیک واقعی این را نشان می‌دهد.

**انتظار واقع‌بینانه از پینگ:** رفت‌وبرگشت ایران ↔ اروپا روی فیبر در بهترین حالت حدود
۸۰ تا ۱۲۰ میلی‌ثانیه است (سرعت نور + مسیرها). رسیدن به ۵۰ میلی‌ثانیه از ایران به یک
سرور اروپایی عملاً ممکن نیست، ولی همین مسیر می‌تواند از ۲۵۰ به حدود ۹۰ تا ۱۳۰ بیاید و
مهم‌تر از عدد، **پایدار** شود؛ همراه با DNS سالم و بدون قطعی. عددهایی که این پنجره
نشان می‌دهد پینگ واقعی همان لحظه روی همان سرور بازی است، نه تخمین.

### ذخیره کردن یک اتصال

هنگام ذخیره، اگر فیلدی خالی مانده باشد برنامه اول نام همان فیلدها را نشان می‌دهد و می‌پرسد؛
ساکت ذخیره نمی‌کند. اگر نامی را بگذارید که اتصال دیگری دارد، می‌پرسد و در صورت تأیید یک شماره
به آخر نام اضافه می‌کند تا «مسیر ثابت بازی» و انتخاب خودکار همیشه یک معنی داشته باشند.

### کارهای روی لیست

| دکمه | کار |
|---|---|
| **Duplicate** | یک رونوشت از ورودی انتخاب‌شده برای آزمایش نسخه دیگر همان پروکسی |
| **Sort: delay** | مرتب‌کردن بر اساس تأخیر اندازه‌گیری‌شده (تست‌نشده‌ها آخر) |
| **Save to file / Load from file** | ذخیره همه اتصال‌ها در یک فایل JSON و بردنش به سیستم دیگر |
| **Carries** (ستون) | هر ورودی می‌گوید چه چیزی را می‌تواند حمل کند: بازی / فقط تلگرام / فقط نام‌ها |
| **Last test** (ستون) | ساعت آخرین تست هر ورودی |

### افزودن دسته‌ای (Import many)

در پنجره Import می‌توانید چند اتصال را با هم بریزید — هر خط یک ورودی، یا حتی یک فایل/کانفیگ چندخطی
(WireGuard یا JSON کامل که در چند خط آمده). پیش‌نمایش قبل از افزودن نشان داده می‌شود و نوع هر ورودی
خودکار تشخیص داده می‌شود.

### انتخاب مسیر در لحظه اجرا

* **Pinned game route** — اگر یک اتصال را پین کنید، همان اول تست می‌شود؛ سالم بود، بازی از آن می‌رود.
* اگر مسیری که پین کرده‌اید **OpenVPN/WireGuard/کانفیگ دستی** باشد، در بودجه یک‌دقیقه‌ای تست نمی‌شود
  (موقع اجرا بالا می‌آید) و همین درست است: برنامه آن را به‌عنوان «خراب» کنار نمی‌گذارد و بازی از همان می‌رود.
* اگر مسیر پین‌شده پاک شده یا خاموش باشد، خط پایین جدول همین را می‌گوید: «… (پیدا نشد؛ مسیر خودکار
  استفاده می‌شود)». هیچ‌وقت مسیر دیگری به‌جای آن، بی‌خبر از شما، جا زده نمی‌شود.
* **خودکار** — همه اتصال‌های روشنِ «شرکت در انتخاب مسیر» تست می‌شوند و **سریع‌ترین** انتخاب می‌شود.
* **Group healthy proxies and keep the fastest** — پروکسی‌های سالم در یک گروه `urltest` قرار می‌گیرند
  و اگر یکی از کار افتاد، sing-box خودش می‌رود روی بعدی (بدون قطع‌شدن بازی).
* **If the chosen route fails, use the automatic one** — مسیر دستی خراب بود، برنامه به WARP برمی‌گردد.
* **Proxy-only mode** — اگر ساخت کارت شبکه TUN ممکن نبود، پروکسی به‌صورت پورت SOCKS محلی به همان
  JVM بازی داده می‌شود و بقیه سیستم دست‌نخورده می‌ماند.

### قطع امن (kill-switch)

اگر تیک Kill switch را بزنید و تونل وسط بازی بمیرد، برنامه آدرس سرور را blackhole می‌کند و بازی را
می‌بندد تا ترافیک از مسیر بدون تونل بیرون نزند. پیش‌فرض **خاموش** است (چون VPN و این قابلیت‌ها
می‌توانند روی پینگ اثر بگذارند) و بدون ادمین هم کار نمی‌کند.

### نکته‌ها

* MTProto فقط برای تلگرام است و **نمی‌تواند** ترافیک بازی را حمل کند؛ فقط تست/تأخیر آن ثبت می‌شود.
* DNS وارد‌شده (DoH/DoT) هم برای رزولو همان سرور بازی استفاده می‌شود، هم قابل تست است.
* هیچ پروکسی سیستمی تنظیم نمی‌شود؛ فقط ترافیک خودِ بازی از اتصال انتخابی می‌رود.

### پنجره و نمایش

* برنامه از **مقیاس نمایش ویندوز** (۱۲۵٪/۱۵۰٪) پیروی می‌کند: کل پنجره‌ها یک بار و فقط یک بار به اندازه آن صفحه
  بزرگ می‌شوند، پس متن بزرگ‌تر از کادر خودش نمی‌زند و بریده نمی‌شود. همه بخش‌ها یک اندازه بزرگ می‌شوند، از
  جمله تیتر کارت‌ها، نوار بالای برنامه و عقربه‌های پینگ.
* تب **خانه و اجرا** با عرض پنجره کشیده می‌شود؛ دکمه «بهینه‌سازی و اجرای بازی» همیشه کامل دیده می‌شود و روی
  هیچ فیلدی نمی‌افتد، و سه عقربه پینگ/مسیر/تونل زیرنویس خودشان را کامل نشان می‌دهند.
* ردیف‌های دکمه‌دار (در تب‌های اتصالات و شبکه) با باریک‌شدن پنجره به خط بعد می‌روند و **ارتفاع خودشان را زیاد
  می‌کنند**، پس هیچ دکمه‌ای نصفه پنهان نمی‌ماند.
* هر پنجره با اندازه واقعی همان صفحه باز می‌شود؛ پنجره‌ای که از صفحه بلندتر است، خودش را داخل صفحه
  نگه می‌دارد و محتوایش اسکرول می‌شود (پنجره ویرایش اتصال).
* جدول‌ها وقت تازه‌سازی چشمک نمی‌زنند، سطر انتخاب‌شده سر جایش می‌ماند و سطرهایشان با ویندوز بزرگ می‌شوند.
* عوض‌کردن زبان پنجره را از نو می‌سازد، ولی همان تب، همان سطر جدول و همان نسخه انتخاب‌شده برمی‌گردد،
  متن لاگ پاک نمی‌شود، و سطرهای اجرای در جریان هم سر جای خودشان می‌مانند. تب «گزارش» از همان اول، لاگ همین
  اجرا را نشان می‌دهد (نه یک کادر خالی).

## تب‌ها

| تب | کاربرد |
|---|---|
| **خانه و اجرا** | انتخاب سرور/نسخه/نام بازیکن و دکمه اجرا + مراحل زنده |
| **سرورها** | افزودن سرور جدید (نام، آدرس، پورت، IP جایگزین) |
| **اتصالات** | افزودن/ویرایش پروکسی، DNS، WireGuard و کانفیگ دستی + تست تک‌تک و گرفتن تأخیر + افزودن دسته‌ای |
| **شبکه و تونل** | اسکن endpointها، تست اتصال سرور، پاک‌سازی |
| **بهینه‌سازی** | روشن/خاموش کردن هر بهینه‌سازی + اجرای فوری |
| **نسخه‌ها** | خواندن نسخه‌های TLauncher/ماینکرفت و انتخاب پوشه |
| **تنظیمات** | زبان (فارسی/English)، پوشه بازی، مسیر Java |
| **گزارش** | لاگ کامل برنامه و لاگ موتور تونل |

## پرسش‌های رایج

**پوشه نسخه‌ها را خودش پیدا می‌کند؟**
بله. `%APPDATA%\.minecraft\versions`، `%APPDATA%\minecraft\versions` و چند مسیر رایج دیگر را
می‌گردد؛ اگر پیدا نکرد، در تب «نسخه‌ها» دکمه «انتخاب پوشه» را بزنید.

**اکانت پریمیوم دارم؛ کار می‌کند؟**
این نسخه بازی را با نام آفلاین اجرا می‌کند (مناسب سرورهای کرک/TLauncher). برنامه قبل از اجرا
یک «آزمایش ورود» انجام می‌دهد و اگر سرور در حالت آنلاین (پریمیوم) باشد، هشدار می‌دهد.

**چه چیزی از من جایی می‌رود؟**
هیچ‌چیز. تنها ارتباط‌های بیرونی: دانلود موتور تونل (از GitHub) و ثبت کلید WARP در API کلادفلر —
دقیقاً مثل اپ رسمی 1.1.1.1. هیچ آمار یا اطلاعاتی ارسال نمی‌شود.

**چرا ادمین لازم است؟**
ساخت اینترفیس TUN، اضافه‌کردن مسیر، نوشتن در `hosts` و تغییر طرح انرژی در ویندوز فقط با دسترسی
ادمین ممکن است.

## ساخت از سورس

```powershell
# روی ویندوز با .NET SDK
dotnet build ServerHelp/src/ServerHelp/ServerHelp.csproj -c Release -p:Platform=x64
```

خروجی در `ServerHelp/src/ServerHelp/bin/x64/Release/net48/ServerHelp.exe` ساخته می‌شود.
اگر فایل‌های `src/ServerHelp/vendor/sing-box.exe` و `vendor/wintun.dll` موجود باشند، داخل exe
جاسازی می‌شوند؛ در غیر این صورت برنامه در اولین اجرا آن‌ها را دانلود می‌کند.
ورک‌فلوی [`.github/workflows/serverhelp-build.yml`](../.github/workflows/serverhelp-build.yml)
همین کار را به‌صورت خودکار روی GitHub انجام می‌دهد و exe را به‌عنوان Release منتشر می‌کند.

## اجزای داخلی

| بخش | توضیح |
|---|---|
| `Core/` | مسیرها، لاگ، JSON بدون وابستگی، دوزبانه، تنظیمات، مدل و پارسر اتصال‌ها |
| `Net/` | تست TCP/DNS/DoH، پینگ Minecraft، SOCKS5/HTTP، کلاینت DNS (udp/tcp/DoT/DoH)، تستر اتصال‌ها، اسکن و ثبت WARP |
| `Tunnel/` | ساخت کانفیگ sing-box (اعتبارسنجی‌شده با schema رسمی نسخه 1.14.3)، تونل آزمایشی تست، اجرای تونل، مسیرها، hosts، blackhole |
| `Sys/` | بهینه‌سازی سیستم و بازگردانی |
| `Mc/` | خواندن نسخه‌ها، پیدا کردن Java، ساخت فرمان اجرا، اجرای بازی |
| `Orchestration/` | خط لوله یک‌دقیقه‌ای «تشخیص → بهینه‌سازی → تونل → اجرا» |
| `Ui/` | رابط کاربری فارسی/انگلیسی راست‌به‌چپ |

مجوز: MIT — همراه با `sing-box` (GPLv3) و `wintun.dll` (مجوز WireGuard، قابل بازتوزیع) به‌صورت
فایل اجرایی جداگانه که در زمان اجرا کنار برنامه باز می‌شود.
