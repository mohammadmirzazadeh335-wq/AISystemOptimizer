# راهنمای فارسی — AI System Optimizer

> این فایل راهنمای کامل برنامه است: از دانلود تا استفادهٔ هر بخش، و توضیح اینکه چه چیزی تأیید شده
> و چه چیزی هنوز تأیید نشده. آخرین بخش را حتماً بخوانید.

---

## ۱. دانلود برنامه

**به هیچ نصب دیگری نیاز ندارید** — نه Visual Studio، نه .NET SDK، نه Runtime. فایل اجرایی
خودکفاست.

1. صفحهٔ Releases را باز کنید:
   **[github.com/mohammadmirzazadeh335-wq/AISystemOptimizer/releases/latest](https://github.com/mohammadmirzazadeh335-wq/AISystemOptimizer/releases/latest)**
2. در بخش **Assets** فایل **`AIOptimizer.exe`** را دانلود کنید (حدود ۶۶ مگابایت).
3. هر جایی که خواستید بگذارید: Desktop، یک پوشه، یا فلش مموری. نصب نمیخواهد.
4. **راست‌کلیک → Run as administrator** برای اجرای اول.
   - بدون دسترسی ادمین هم برنامه کار می‌کند، اما تغییر سرویس‌ها، ساخت Restore Point و بعضی
     ورودی‌های Startup **رد می‌شوند** — این عمدی است، نه باگ.
5. ممکن است Windows SmartScreen هشدار «ناشر ناشناس» بدهد، چون فایل امضای دیجیتال تجاری ندارد.
   گزینهٔ **More info → Run anyway**.

### بررسی سلامت فایل دانلودشده (اختیاری ولی توصیه‌شده)

در PowerShell:

```powershell
certutil -hashfile AIOptimizer.exe SHA256
```

مقدار چاپ‌شده باید دقیقاً با محتوای فایل `AIOptimizer.exe.sha256` روی همان صفحهٔ Release یکی باشد.
این فایل هش برای نسخهٔ فعلی این است:

```
4db1654bd3d7fa1ed37fca79e2faa0f39fdc2798eee2a0d16781d5edaed0a662
```

اگر یکی نبود، فایل را دور بریزید و دوباره دانلود کنید.

## ۲. گرفتن سورس‌کد و ساختن خودتان (اختیاری)

اگر می‌خواهید خودتان کامپایل کنید:

```powershell
# پیش‌نیاز: .NET SDK 8
git clone https://github.com/mohammadmirzazadeh335-wq/AISystemOptimizer.git
cd AISystemOptimizer

dotnet build -c Release                      # ساخت
dotnet test  -c Release                      # ۴۹۲ تست — باید همه سبز باشند

# ساخت نسخهٔ تک‌فایل خودکفا (همان فایلی که در Releases است):
dotnet publish src/AISystemOptimizer.App/AISystemOptimizer.App.csproj `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:PortableName=AIOptimizer -o portable
```

خروجی: `portable\AIOptimizer.exe`

## ۳. اولین اجرا

| کار | چرا |
|---|---|
| برنامه را با ادمین اجرا کنید | برای تغییر سرویس، Restore Point و Startup |
| صبر کنید اولین اسکن تمام شود | چند ثانیه؛ در این مدت داشبورد پر می‌شود |
| در **Settings** تنظیمات را ببینید | همهٔ گزینه‌ها با توضیح فارسی/انگلیسی و مقدار پیش‌فرض امن |
| هیچ چیزی خودکار تغییر نمی‌کند | حالت پیش‌فرض «Manual» است و هر تغییر تأیید می‌خواهد |

فایل تنظیمات: `%LOCALAPPDATA%\AISystemOptimizer\config.json`
(یک نمونهٔ کامل و توضیح‌دار در `config/config.json` در مخزن هست.)

**حالت Portable:** اگر می‌خواهید همه‌چیز کنار خود فایل اجرایی باشد (مثلاً روی فلش):

```powershell
$env:AISYSTEMOPTIMIZER_PORTABLE = "1"
.\AIOptimizer.exe
```

## ۴. بخش‌های برنامه

### 🏠 Dashboard
نمای کلی: RAM، CPU، GPU، دیسک، شبکه و Uptime. اعداد از همان APIهایی می‌آیند که Task Manager
استفاده می‌کند؛ اگر عددی با Task Manager تفاوت داشت، آن یک **باگ** است، نه تقریب.

### 🔍 Processes
فهرست همهٔ فرایندها با دسته‌بندی (`CRITICAL`, `SYSTEM`, `DRIVER`, `SECURITY`, `USER APPLICATION`,
`BACKGROUND APPLICATION`, `LAUNCHER`, `UPDATER`, `CLOUD SYNC`, `TELEMETRY`) و سطح ریسک.
فرایندهای حیاتی فقط **نمایش** داده می‌شوند و هرگز بسته نمی‌شوند.

### ⚡ Optimization & Memory
اینجا بهینه‌سازی انجام می‌شود:

1. **Analyse** بزنید — برنامه سیستم را اسکن می‌کند.
2. **Optimize** بزنید — **قبل از اجرا، فهرست کارهایی که می‌خواهد انجام دهد را نشان می‌دهد**،
   با دلیل هرکدام.
3. اگر تأیید کنید، اجرا می‌شود و نتیجه **قبل/بعد** اندازه‌گیری و ثبت می‌شود.

اگر رسیدن به هدف RAM (پیش‌فرض ۳۵٪) بدون کار ناامن ممکن نباشد، برنامه می‌گوید:

> **Safe optimization limit reached.**

و کاری که لازم دارد را انجام **نمی‌دهد** (خاموش کردن سرویس‌های ویندوز، Defender، درایورها…).
این یک شکست نیست؛ درست‌ترین رفتار ممکن است.

### 🎮 Game Mode
برای یک بازی در حال اجرا: اولویت را تا `AboveNormal` بالا می‌برد و برنامه‌های پس‌زمینهٔ تأییدشده
را **فقط برای همان جلسه** متوقف می‌کند. با بسته شدن بازی همه‌چیز برمی‌گردد.

### 🎮 Game & App Optimizer (بخش جدید)
پروفایل اختصاصی برای هر برنامه:

- **+ Add Game / App** → انتخاب فایل `.exe`.
  فایل **فقط خوانده و هش می‌شود؛ هرگز برای بازرسی اجرا نمی‌شود**، و نام فایل ملاک نیست:
  هویت = مسیر کامل + SHA-256 + ناشر + نسخه.
- کارت هر برنامه: وضعیت زنده (`Not Running` / `● Running · PID 1234`)، حالت پروفایل، حافظه، CPU،
  GPU و دکمه‌های **Optimize / Launch / Profile / Remove**.
- چهار حالت: **Safe** (حداقلی و کاملاً برگشت‌پذیر) · **Balanced** (پیش‌فرض) · **Performance**
  (تهاجمی‌ترین چیزی که داخل مدل ایمنی جا می‌شود) · **Custom**.
  **حالت «Unsafe» وجود ندارد.**
- **Restore Engine اجباری:** قبل از هر تغییر، مقدار اصلی (OriginalValue)، مقدار جدید، زمان،
  شناسهٔ برنامه، دلیل و اطلاعات بازگردانی ذخیره می‌شود. با خروج برنامه همه‌چیز برمی‌گردد و
  **بازخوانی می‌شود** تا مطمئن شوند برگشته است.
- **بازیابی از سقوط:** اگر برنامه وسط یک جلسه بسته شود، اجرای بعدی پیام
  **«An optimization session was interrupted.»** را با گزینه‌های **Restore / Review / Keep the changes**
  نشان می‌دهد. هیچ بازگردانی خودکار و خطرناکی انجام نمی‌شود.
- **AI Analyze:** مدل محلی می‌تواند پیشنهاد بدهد، اما **فقط از یک فهرست بسته**
  (`close_process`, `change_priority`, `adjust_power`, `set_graphics_preference`).
  هر اکشن ناشناس، ریسک ناشناس، هدف نامعتبر یا «confidence» خارج از ۰ تا ۱ **رد می‌شود**.
  هیچ دستوری از متن آزاد ساخته و اجرا نمی‌شود.
- **تغییر فایل اجرایی = تعلیق پروفایل:**
  **«Executable changed. Profile requires verification.»** — هرگز بی‌صدا ادامه نمی‌دهد.

### 🚀 Start-up Programs
ورودی‌های Startup با دسته‌بندی ریسک. قبل از غیرفعال‌سازی، **خط فرمان اصلی ذخیره می‌شود** تا
بازگردانی دقیق ممکن باشد. برنامه‌های حیاتی ویندوز غیرفعال نمی‌شوند.

### ⚙️ Windows Services
سرویس‌های شخص ثالث با توضیح و سطح ریسک. سرویس‌های ویندوزی، Defender و فایروال
**حتی با دسترسی ادمین هم** قابل توقف/غیرفعال‌سازی نیستند.

### 📊 History & Reports
هر عملیات با قبل/بعد و نتیجه‌اش ثبت می‌شود. گزارش‌ها در پوشهٔ `Reports` ذخیره می‌شوند.

### 🤖 AI Assistant (اختیاری)
روی سرور **محلی** Ollama یا llama.cpp کار می‌کند. بدون آن هم **همهٔ** قابلیت‌های برنامه کار می‌کند؛
هیچ قابلیتی به AI وابسته نیست. مدل فقط «پیشنهاد» می‌دهد؛ اجرا از مسیر عادی ایمنی می‌گذرد.

## ۵. تضمین‌هایی که در کد اجرا می‌شوند (نه فقط در حرف)

- ✗ غیرفعال کردن Windows Defender، فایروال یا UAC
- ✗ بستن فرایندهای حیاتی (`System`, `csrss`, `lsass`, `winlogon`, `dwm`, `explorer`, `svchost`, …)
- ✗ دست زدن به درایورهای سخت‌افزار
- ✗ غیرفعال کردن یا تغییر اندازهٔ pagefile
- ✗ پاک کردن «Standby List» برای زیباتر شدن عدد RAM
- ✗ دور زدن UAC
- ✗ غیرفعال کردن Windows Update
- ✗ تغییر کلیدهای رجیستری مستندنشده
- ✗ Defragment کردن SSD
- ✗ ادعای سرعت‌گرفتن بدون اندازه‌گیری — **FPS هرگز ادعا نمی‌شود** و اگر منبع معتبری نباشد
  مقدار `N/A - FPS source unavailable.` نمایش داده می‌شود
- ✗ وعدهٔ درصد ثابت RAM؛ اگر نشد، «Safe optimization limit reached.» گفته می‌شود

## ۶. عیب‌یابی سریع

| نشانه | کار |
|---|---|
| SmartScreen هشدار می‌دهد | More info → Run anyway (فایل امضای تجاری ندارد) |
| بعضی کارها «رد شد» | برنامه را با Run as administrator اجرا کنید |
| عدد RAM با Task Manager فرق دارد | این باگ است — گزارش دهید؛ لطفاً با اسکرین‌شات هر دو |
| GPU/Temperature نشان می‌دهد `N/A` | درایور آن شمارنده را ارائه نمی‌دهد؛ برنامه عدد نمی‌سازد |
| AI Analyze چیزی پیشنهاد نمی‌کند | Ollama در حال اجرا نیست، یا پیشنهادهای مدل از فیلتر ایمنی رد شده‌اند (دلیلش نوشته می‌شود) |
| می‌خواهم همه‌چیز را برگردانم | در بخش Optimization دکمهٔ **Undo**؛ در Game & App Optimizer دکمهٔ **End session and restore** |
| برنامه روی «گرفتن اطلاعات سیستم» ماند | این باگ نسخهٔ ۱.۰.۰ بود (خواندن‌های WMI بدون timeout). در **v1.0.1** رفع شده؛ حتماً نسخهٔ جدید را از صفحهٔ Releases بگیرید |
| فایل‌های لاگ کجاست | `%LOCALAPPDATA%\AISystemOptimizer\Logs` (یا کنار EXE در حالت Portable) |

## ۷. صادقانه: چه چیزی تأیید شده و چه چیزی نه

این را نخوانید و به برنامه اعتماد نکنید، پس بخوانید:

| ادعا | وضعیت |
|---|---|
| کامپایل تمیز (Debug و Release، ۰ warning) | **تأییدشده** |
| ۴۹۲ تست، همه سبز، هیچ تستی حذف نشده | **تأییدشده** |
| منطق ایمنی، اعتبارسنجی مسیر، هش، پروفایل‌ها، بازگردانی، واژگان AI | **تأییدشده** (تست واحد) |
| فایل اجرایی ساخته شده و تکرارپذیر است | **تأییدشده** |
| **کار کردن واقعی روی Windows 11**: انتخابگر فایل، تغییر اولویت، تغییر Power Plan، ترجیح گرافیک، Game Mode، بنچمارک، رندر رابط | **تأیید نشده** — این محیط ویندوز نیست |
| Game & App Optimizer روی ویندوز | **تأیید نشده** — ۲۰ آزمون در `docs/GAME_APP_OPTIMIZER_SMOKE_TEST.md` نوشته شده و **هیچ‌کدام اجرا نشده** |

**نتیجه:** منطق برنامه تست‌شده و سالم است، اما رفتار آن روی ویندوز ۱۱ تا وقتی فهرست ۲۰ مرحله‌ای روی
یک ماشین واقعی اجرا نشود «تأیید نشده» می‌ماند. اگر خودتان آن را اجرا کردید و چیزی خطا داد، **یک باگ
پیدا کرده‌اید**؛ در GitHub یک Issue باز کنید و همان مرحله + پیام خطا را بنویسید.
