# Testing

## Principles

1. **Real components.** Tests use the real SQLite database, the real services, the
   real Qt widgets and the real theme system. There are no mock objects standing in
   for the product's own code.
2. **Isolation.** Every test gets a fresh temporary workspace (`MYAI_STUDIO_HOME`),
   so nothing can read or corrupt a developer's data.
3. **Headless by default.** Qt runs with `QT_QPA_PLATFORM=offscreen`; the same tests
   pass on a desktop.
4. **Evidence over claims.** A feature is "done" only when a test that exercises it
   passes, or when a screenshot generated by real execution shows it.

## Running

```bash
# everything
./scripts/run_tests.sh -q

# one layer
./scripts/run_tests.sh tests/unit -q
./scripts/run_tests.sh tests/ui -q

# one file, verbose
./scripts/run_tests.sh tests/ui/test_main_window.py -v
```

On Windows:

```powershell
.venv\Scripts\python -m pytest -q
```

## What each directory covers

| Directory | Scope | Examples |
| --- | --- | --- |
| `tests/unit` | pure logic, no widgets | token completeness, i18n catalogue parity, markdown escaping, SQLite CRUD/cascades, settings validation, DPAPI/Fernet secrets, zip backups, toolchain detection, real `python`/`gcc`/`node` runs, timeout and cancel, project path guards |
| `tests/ui` | real widgets on the offscreen platform | window bootstrap, typing + Enter to send, conversation switching, theme switch repaint, RTL flip, inspector animation, settings dialog pages, accent change, Code Studio with real folders/files/processes, compile errors, missing toolchains, DPI rebuilds |
| `tests/integration` | multiple layers together | restart persistence, architecture layering guard, backup/restore, export |

## Visual verification

`scripts/capture_ui.py` drives the real window and captures nine PNGs into
`artifacts/ui/`:

| File | Shows |
| --- | --- |
| `01_welcome_dark_fa.png` | RTL welcome state, suggestion cards, inspector |
| `02_conversation_dark_fa.png` | message thread, composer notice, activity feed |
| `03_sidebar_collapsed.png` | collapsed sidebar, icon rail |
| `04_conversation_light_fa.png` | light theme in RTL |
| `05_conversation_dark_en.png` | English LTR layout |
| `06_placeholder_code_en.png` | phase-locked route placeholder |
| `07b_confirm_dialog_only.png` | destructive confirmation dialog |
| `08_settings_appearance.png` | settings dialog, theme and accent pickers |

Regenerate after UI changes and inspect the images — this is how layout defects
were found during Phase 1 (clipped inspector cards, raw translation keys, mixed
digit styles).

## Adding a test

- New widget behaviour → `tests/ui/`, use the `ui` fixture (`window, context, theme`).
- New service/repository rule → `tests/unit/` with the `ctx` or `db` fixture.
- New cross-layer flow → `tests/integration/`.
- New translation key → covered automatically by `test_every_key_used_in_source_exists`
  and `test_catalogues_have_identical_keys`; no extra test needed, but both catalogues
  must be updated in the same commit.
