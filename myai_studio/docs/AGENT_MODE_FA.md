# حالت عامل — راهنمای کاربر (فارسی)

حالت عامل به مدل اجازه می‌دهد به‌جای پاسخ‌دادنِ صرف، **کار** کند: فایل‌های پروژهٔ باز
را فهرست و خوانده، فایل بنویسد یا حذف کند، با زنجیره‌ابزار نصب‌شده روی همین دستگاه اجرا
کند، وب را جست‌وجو کند، مسئله‌های گیت‌هاب را بخواند و نکته‌ها را در حافظه نگه دارد.
دامنه عمداً باریک است: مدل فقط بیست‌ودو ابزار ثبت‌شده را در اختیار دارد، هر فراخوانی حساس
تأیید شما را می‌خواهد و ابزاری که نمی‌تواند کار کند دقیقاً می‌گوید چرا.

---

## ۱. بازکردن

1. در نوار کناری روی **حالت عامل** بزنید (یا کلید سرصفحه را روی **عامل** بگذارید).
2. بهتر است نخست پوشهٔ پروژه را در **استودیوی کد** باز کنید؛ ابزارهای فایل فقط داخل همان
   پوشه کار می‌کنند.
3. مدل را از فهرست **مدل** انتخاب کنید. نشان کنار وظیفه می‌گوید مدل فراخوانی ابزار را
   پشتیبانی می‌کند یا نه. کلید شما مانند گفتگو به OpenRouter فرستاده می‌شود.
4. هدف را بنویسید («فایل `hello.py` را بخوان، توضیح بده چه می‌کند و فایل‌های پروژه را
   فهرست کن») و **اجرای عامل** را بزنید (یا `Ctrl+Enter`).

## ۲. کارت ابزارها

ستون چپ همهٔ بیست‌ودو ابزار را با سطح ریسک و دسترس‌بودن زنده نشان می‌دهد:

| ابزار | کار | ریسک |
| --- | --- | --- |
| `list_files` | فهرست درخت پروژه | خواندن |
| `read_file` | خواندن فایل متنی (با سقف اندازه؛ فایل دودویی رد می‌شود) | خواندن |
| `write_file` | نوشتن یا بازنویسی فایل | نوشتن |
| `make_folder` | ساخت پوشهٔ تو‌در‌تو داخل پروژه (مسیر فرار رد می‌شود) | نوشتن |
| `create_project` | ساخت پوشهٔ پروژهٔ واقعی و ثبت آن در استودیوی کد | نوشتن |
| `search_files` | جست‌وجوی بی‌توجه به بزرگی/کوچکی حروف با فیلتر اختیاری `*.py` | خواندن |
| `delete_file` | حذف یک فایل | نوشتن |
| `run_file` | اجرا با زنجیره‌ابزار شناسایی‌شده و محدودیت زمانی | اجرا |
| `remember` / `recall` | ذخیره و جست‌وجوی نکته‌های ماندگار در حافظه | نوشتن / خواندن |
| `save_output` | ذخیرهٔ پیش‌نویس در استودیوی خروجی | نوشتن |
| `web_search` | جست‌وجو در نقطهٔ پایانی سازگار با SearxNG | شبکه |
| `github_list_issues` | فهرست مسئله‌های باز یک مخزن | شبکه |
| `github_comment` | نوشتن دیدگاه روی یک مسئله | شبکه |
| `project_map` | نقشهٔ ساختاری: زبان‌ها با شمار واقعی خطوط، بزرگ‌ترین فایل‌ها، نقطه‌های ورود | خواندن |
| `find_files` | جست‌وجوی گلوب (`**/*.py`) با اندازه، تازه‌ترین اول | خواندن |
| `read_lines` | بازهٔ شماره‌دار خطوط یک فایل (برای فایل‌های بزرگ) | خواندن |
| `scan_todos` | همهٔ TODO / FIXME / HACK / XXX / BUG با محل | خواندن |
| `diff_files` | دیف یکپارچهٔ واقعی بین دو فایل پروژه | خواندن |
| `apply_patch` | اعمال هانک‌های `@@`؛ همه‌یا‌هیچ، با تحمل جابه‌جایی شمارهٔ خط | نوشتن |
| `fetch_url` | خواندن یک صفحهٔ عمومی به‌صورت متن (خواندن صفحه، نه جست‌وجو) | شبکه |
| `generate_image` | **همیشه دردسترس نیست** — سرویس‌دهندهٔ تصویر وجود ندارد | شبکه |

عدد «N از ۲۲ آماده» از شرط‌های واقعی حساب می‌شود. ردیف *دردسترس نیست* دلیل دقیق را
همراه دارد (پوشهٔ پروژه نیست، شبکه خاموش است، نقطهٔ پایانی تنظیم نشده، توکن نیست،
سرویس‌دهندهٔ تصویر نیست). نشانگر را روی ردیف نگه دارید تا متن کامل را ببینید؛ همان دلیل
در تنظیمات ← عامل هم تکرار می‌شود.

### ۲.۱ هفت ابزار کاوش و ویرایش

این‌ها پس از فاز ۵ اضافه شدند تا عامل روی یک پروژهٔ واقعی واقعاً کاربردی باشد،
نه فقط بتواند کل فایل را بازنویسی کند:

* **`project_map`** نخستین فراخوانی پیشنهادی است: زبان‌ها، شمار واقعی خطوط،
  پنج فایل بزرگ و نقطه‌های ورود، تا مدل نام فایل را حدس نزند.
* **`find_files`** پاسخ «این کجاست؟» را با گلوب می‌دهد و الگوهایی که از پروژه
  بیرون می‌زنند را رد می‌کند.
* **`read_lines`** به‌جای فایل چهارهزارخطی، پنجرهٔ شماره‌دار می‌خواند.
* **`scan_todos`** همان نشانه‌هایی را می‌آورد که یک نگه‌دارنده grep می‌کند.
* **`diff_files`** دیف یکپارچهٔ واقعی `difflib` را نشان می‌دهد یا می‌گوید فایل‌ها
  یکسان‌اند.
* **`apply_patch`** یک دیف یکپارچه را روی یک فایل اعمال می‌کند. زمینه باید دقیق
  بخواند؛ شمارهٔ خط می‌تواند جابه‌جا شده باشد. اگر یک هانک شکست بخورد، **هیچ‌چیز
  نوشته نمی‌شود** — فایل نیمه‌کاره وجود ندارد. ابزار «نوشتن» است، پس پنجرهٔ تأیید
  خود پچ را نشان می‌دهد.
* **`fetch_url`** یک صفحهٔ عمومی http(s) را با همان خوانندهٔ صفحهٔ پژوهش وب
  می‌خواند. ابزار «شبکه» است: به «اجازهٔ ابزارهای شبکه» و تأیید معمول نیاز دارد.

## ۳. تأیید

با روشن‌بودن **پیش از نوشتن، اجرا و تماس شبکه اجازه بگیر** (پیش‌فرض)، هر فراخوانی
نوشتن/اجرا/شبکه یک دیالوگ مُدال باز می‌کند که نام ابزار و **آرگومان‌های دقیق به‌صورت
JSON** را نشان می‌دهد. همان JSON را بخوانید؛ تنها چیزی که اجرا می‌شود همان است.

- **تأیید** فراخوانی را اجرا می‌کند.
- **رد** گام را «ردشده» ثبت می‌کند. هیچ فایلی نوشته، حذف یا اجرا نمی‌شود و هیچ درخواستی
  فرستاده نمی‌شود. مدل رد شدن را می‌بیند و می‌تواند راه دیگری پیشنهاد دهد.

این دیالوگ را نمی‌توان برای یک ابزار خاص دور زد؛ کلید کلی در تنظیمات ← عامل است. خاموش
کردن آن باعث می‌شود فراخوانی‌های حساس بدون پرسش اجرا شوند — فقط وقتی وظیفه را کامل
می‌شناسید این کار را بکنید.

## ۴. اجرا

ستون راست **خط زمانی** را نشان می‌دهد:

- *اندیشه* — پیام میانی مدل؛
- *ابزار* — فراخوانی، آرگومان‌ها، نتیجه (محتوای فایل، خروجی/خطا، ردیف‌های HTTP) و مدت؛
- *ردشده* / *خطا* — آنچه رخ داده، بی‌کم‌وکاست، همراه با متن خطای خودِ ابزار؛
- *پاسخ* — پاسخ نهایی؛ نشان وضعیت یکی از «کامل شد»، «لغو شد»، «سقف گام» یا «ناموفق» است.

دکمهٔ **توقف** جریان، ابزار در حال اجرا و حلقه را متوقف می‌کند. حلقه با **حداکثر گام**
(۴، ۸، ۱۲، ۲۰ یا ۵۰؛ پیش‌فرض ۱۲ در `agent.max_steps`) محدود است. با رسیدن به سقف، اجرا
می‌ایستد و همان را می‌گوید؛ نتیجه‌ای از خود نمی‌سازد.

**اجراهای اخیر** اجراهای همین نشست را نگه می‌دارد؛ روی هر ردیف بزنید تا خط زمانی‌اش باز شود.

## ۵. تنظیم ابزارهای شبکه (تنظیمات ← عامل و ابزارها)

| تنظیم | اثر |
| --- | --- |
| پیش از نوشتن، اجرا و تماس شبکه اجازه بگیر | دروازهٔ تأیید کلی |
| ابزارهای شبکه | کلید اصلی `web_search` و `github_*` (پیش‌فرض خاموش) |
| حداکثر گام | بین ۱ تا ۵۰ |
| نقطهٔ پایانی جست‌وجو | نشانی سازگار با SearxNG که `?q=…&format=json` را می‌پذیرد (مثلاً `https://searx.example/search`) |
| توکن گیت‌هاب | توکن دسترسی شخصی در مخزن رمزنگاری‌شده؛ برای ابزارهای گیت‌هاب لازم است |

هر دو فیلد اعتبارنامه دکمهٔ ذخیره دارند و توکن دکمهٔ پاک‌کردن هم دارد. رازهای ذخیره‌شده
هرگز در پشتیبان، گزارش یا خروجی نمی‌آیند. صفحه دسترس‌بودن زندهٔ هر ابزار را تکرار می‌کند
تا ببینید تنظیماتتان دقیقاً چه چیزی را باز کرده است.

## ۶. چه کارهایی نمی‌کند

- بیرون از پوشهٔ پروژه نمی‌نویسد؛ فرار از مسیر، مسیر مطلق و پیوند نمادین پیش از اجرا رد
  می‌شود.
- بدون دروازهٔ تأیید برنامه اجرا نمی‌کند؛ اجرا محدودیت زمانی دارد و قابل توقف است.
- نتیجهٔ ابزار را از خود نمی‌سازد. اگر ابزاری در دسترس نباشد، گام می‌گوید کدام شرط بسته
  است؛ اگر فراخوانی شکست بخورد، خطا بدون تغییر به مدل و خط زمانی برمی‌گردد.
- تصویر تولید نمی‌کند. `generate_image` ثبت شده تا مدل آن را ببیند، اما تا تنظیم یک
  سرویس‌دهندهٔ واقعی تصویر همیشه دردسترس نیست.

## ۷. عیب‌یابی

| نشانه | علت / راه‌حل |
| --- | --- |
| دکمهٔ اجرا غیرفعال است | مدلی انتخاب نشده، متن وظیفه خالی است یا مدل ابزار را پشتیبانی نمی‌کند |
| «کلید OpenRouter را وارد کنید…» | در **تنظیمات هوش مصنوعی** (اتصال و مدل‌ها) کلید را ذخیره کنید |
| همهٔ ابزارهای فایل می‌گویند «هیچ پوشهٔ پروژه‌ای باز نیست» | نخست در استودیوی کد پوشه‌ای باز کنید |
| «دسترسی شبکه خاموش است» | تنظیمات ← عامل ← ابزارهای شبکه |
| «هیچ نقطهٔ پایانی جست‌وجو تنظیم نشده» | تنظیمات ← عامل ← نقطهٔ پایانی جست‌وجو |
| «هیچ توکن گیت‌هابی ذخیره نشده» | تنظیمات ← عامل ← توکن گیت‌هاب |
| نشان «سقف گام» | وظیفه به گام بیشتری نیاز داشت؛ سقف را بالا ببرید یا وظیفه را باریک‌تر کنید |
| نشان «ناموفق» | گام خطا را بخوانید: پیام خود سرویس‌دهنده یا خود ابزار است |
